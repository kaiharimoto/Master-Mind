## State

The 150-node map with hand tracking on, then switched off for a mouse-only tail.

## Vantage

Mind expansion, framed to fit; 36 s at 30 fps.

## What it proves

The four webcam-detected poses in sequence with labels, each mapped to a different map-scale operation, cluster internal arrangement preserved - then the same four operations driven by mouse alone.

## How the cluster move is measured

Two operations move a cluster in this take and they are measured separately,
because one flag covering both could stay green while either regressed.

- **By pose.** Every frame of the tracking section (through frame 781) is asked
  whether a hand grab is live and whether the detector reads a fist. Each
  contiguous run of the same held member set becomes a *pose window* in
  `poseGrabs`: the cluster's label, its member count, its centroid at both ends
  of the hold, the distance between them, the largest drift of any member
  relative to the others, and the frames and seconds the window spans.
  `clusterMovedByPose` is true when some window's centroid travelled more than
  0.5 units; `clusterArrangementPreservedByPose` when no window drifted by more
  than 1e-3.
- **By mouse.** The alt-drag tail, sampled at frames 820 and 890 -- both after
  tracking is switched off -- as `clusterMovedByMouse` and
  `clusterInternalArrangementPreserved`.

All four are declared in the driver's `requires`, so a fist that grabbed
nothing is a failed capture rather than a record with the mouse's result
standing in for it.

## What is deterministic here, and what is not

The take's frames are: the sync service starts from a freshly wiped data
directory seeded from the committed fixtures, `Date.now()` is pinned to a fixed
epoch plus elapsed time, `Math.random` is a seeded PRNG, and the camera pose is
set explicitly rather than left to whatever the previous interaction left
behind. Node ids and relative times are identical from cycle to cycle.

**The pose segmentation inside those frames is not.** The hand detector runs
against the clip asynchronously, so the frame on which a grab begins or ends can
move by a frame or two between runs, and the number of move groups the take
produces varies with it — 26 when the undo tail was first written, 34 on the run
that exposed the difference. The positions ledger returns to its starting values
either way, and `poseGrabs` reports every window the run actually found, so the
claims here are per-run measurements of a take whose boundaries can shift rather
than assertions that two runs produce the same segmentation. The undo tail is
sized for the variation, not for the number one run happened to make.

## Determinism

The sync service is started with a freshly wiped data directory seeded from the
committed fixtures in `seeds/`. Before the app boots, the harness pins
`Date.now()` to a fixed epoch plus elapsed time and replaces `Math.random` with
a seeded PRNG (`harness/capture.mjs`, `SEED`), so generated node ids and
relative times are identical from cycle to cycle. The camera pose is set
explicitly rather than left to whatever the previous interaction left behind.
